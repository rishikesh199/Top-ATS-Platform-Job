01 · Business Problem & Engineering Motivation

What Major Problem This Resolves & Why It Was Built

The Core Business Gap: Point-in-Time Snapshots Are Blind to Market Movement

Public ATS aggregators publish a single daily file (all.parquet, ~5.1M rows) representing only jobs active today. For workforce analysts, recruiters, and market researchers, a raw snapshot cannot answer critical questions:

  • Lifecycle & Longevity: When did a specific job URL first appear, how many days has it stayed open, and when was it removed/filled?
  • Daily Hiring Velocity: How many net new vs. removed jobs happened today by country, company, or role family?
  • Standardization: Raw feeds contain messy timestamps, mixed salary strings, non-normalized commitments (vollzeit, cdi, werkstudent), and uncategorized job titles.
Verified Source: Archive/stapply-documentation.zip::short_documentation.md (L10–28), silver.sql (L26–55).
Problem 1 Solved

Serverless Egress & Memory Limits

Issue: Early Gen 1 runs failed downloading 2–3 GiB directly on Databricks Serverless (file: prefix errors, OOM, timeouts).
Solution: Offloaded acquisition to an ephemeral AWS ECS Fargate container streaming 64 MiB multipart parts directly to S3 with 0 NAT Gateways.

project_architecture_challenges_learnings.py L87–105 · CloudWatch logs.png
Problem 2 Solved

97% Wasted Daily Re-Enrichment

Issue: Re-enriching 5.1M rows daily is costly when ~97% of job URLs carry over unchanged.
Solution: Proved ~3% incremental enrichment in Gen 1/2, then migrated to Lakeflow SDP AUTO CDC FROM SNAPSHOT (SCD Type 2), automatically tracking __START_AT and __END_AT.

Stapply-Export-Dev/README.md L72 · bronze.sql L25–52
Problem 3 Solved

Complex 30-Table Orchestration

Issue: Gen 2 required 7 imperative notebooks and 30 Delta tables (~14–15 min runtime).
Solution: Consolidated into 3 declarative SQL files (9 SDP objects) with built-in CONSTRAINT expectations, cutting runtime to ~8 min.

Task run log.png (~14–15m) → SDP pipeline (2).png (~8m)

Files: Archive/Dockerfile (L1–13), Portfolio/AWS_setup.txt (L40–198).

  1. 1Zero Local Disk: Streams ~2.12 GiB Parquet in memory using 8 MiB HTTP chunks so a 2 GB RAM Fargate container never runs out of disk or memory.

04 · Handover & New-Account Runbook

How Anyone Can Deploy & Run This on a Fresh Databricks Account

Exact handover steps derived from stapply-deploymentNewacc.zip::README.md, config.py, and our Phase 3/4 audit (including pre-run fixes for Newacc).

Step 1 · Prerequisites

Cloud & UC Permissions

Ensure Unity Catalog external location points to your S3 snapshot bucket, Serverless compute is enabled, a SQL Warehouse exists, and your user has CREATE TABLE / CREATE MATERIALIZED VIEW privileges.

Step 2 · Edit config.py

Single Config File

Update S3_BUCKET, CATALOG, SCHEMA, ALERT_EMAILS, and SCHEDULE_TIMEZONE in config.py. Set DEVELOPMENT_MODE = False (L24) for production retries.

Step 3 · Pre-Run Fix

Restore SQL Template

In Newacc bronze.sql (L7, L16), replace the hardcoded S3 URI with '{{S3_PATH}}' so 01_deploy.py Step 2 templating injects your bucket automatically. Skip 02_handover_guide.py.

Step 4 · Deploy & Schedule

Run 01_deploy → 03

Run 01_deploy.py (Run All) to build the SDP pipeline, execute the initial load, publish the 3-page dashboard, and pass the 7-point SQL check. Then run 03_setup_schedules.py.
